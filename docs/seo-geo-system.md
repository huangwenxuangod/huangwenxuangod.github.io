# 文轩博客 SEO / GEO 统一方案

## 这份文档是做什么的

这份文档是文轩博客当前唯一保留的 SEO / GEO 方法论文档，用来统一下面四件事：

1. 我们到底在优化什么
2. 这个站当前卡在哪里
3. 接下来该按什么顺序做
4. 怎么用 AI 把优化流程做成稳定生产系统

`reports/geo-audit.md` 继续保留，但它只是自动生成的审计报告，不承担方法论职责。

## 一、先统一概念：SEO、AEO、GEO 不是三套事

对文轩博客来说，这三件事本质上是一套内容分发系统的三个出口：

- `SEO`：让 Google、Bing、搜索引擎更容易发现、理解、索引和排名。
- `AEO`：让文章更容易被直接抽成答案，出现在摘要、问答、精选片段里。
- `GEO`：让 ChatGPT、Claude、Gemini、豆包这类 AI 在生成回答时，更愿意把你的内容当作可引用材料。

所以我们的优化目标，不是把博客写成“关键词农场”，而是把每篇文章都升级成：

- 能被搜索发现
- 能被机器理解
- 能被 AI 截取引用
- 被引用后还能把读者带回站内继续阅读

一句话概括：`从“有表达的博客”，升级成“可检索、可引用、可沉淀的内容资产”。`

## 二、当前站点现状：已经打了地基，但离“强引用站”还有距离

### 1. 已经具备的基础设施

目前仓库里已经有一批关键基础设施，说明这件事不是从零开始：

- 页面级 canonical、robots、OG、Twitter 元信息
- `Person / WebSite / BreadcrumbList` 结构化数据
- `about` 页面
- 动态 `llms.txt` 和 `llms-full.txt`
- `robots.txt`
- sitemap 对 `indexable` 的支持
- content schema 支持 `updated / description / tags / indexable`
- `gen:meta` 自动生成内容元数据
- `geo:audit` 本地 GEO 审计脚本

这意味着技术层面的“能不能被抓、能不能被识别”，已经跨过第一道门槛。

### 2. 当前真正的瓶颈

根据 [geo-audit.md](/d:/dev/my-project/wenxuan-blog/reports/geo-audit.md) 的最新结果：

- 全站平均中文可引用性约 `52/100`
- 元数据问题已经大幅减少
- 真正拖后腿的，主要不是技术，而是 `段落本身不够可引用`

也就是说，现在的问题不是：

- 搜索引擎根本看不到你
- AI 完全读不懂你

现在的问题更像是：

- 文章有观点，但很多段落不够“自包含”
- 人能读懂，是因为人会自动脑补上下文；AI 截一段出来，就容易失真
- 有情绪、有表达，但缺少“判断句、边界、步骤、证据、对象名”
- 站内主题有雏形，但还没形成真正的专题网络

### 3. 为什么分数会卡在 50 左右

这个分数低，不代表内容差；它更准确地反映了一个事实：

`文章更像“连续阅读作品”，还不够像“可独立抽取的知识单元”。`

GEO / AEO 更偏爱这样的段落：

- 第一段就直接回答问题
- 这段单独被截出来也能读懂
- 里面有明确对象、动作、条件、结论
- 最好还有工具名、步骤、数字、案例、失败细节

而个人博客常见的问题是：

- 情绪和判断有了，结论句不够硬
- 故事很好，但结构不够适合机器截取
- 观点很多，但少“适用场景”和“反例边界”
- 有些文章写得像朋友圈长文，不像答案资产

所以接下来不是“做更多 meta 标签”，而是 `把内容组织方式升级一层`。

## 三、我们真正要做的，不是单篇优化，而是三层结构升级

### 第一层：可发现

目标：让搜索引擎和 AI 爬虫愿意抓、抓得到、知道哪些该收录。

这层已经做了不少，但后续要持续维护：

- 确保每篇值得排名的文章都有 `title / description / updated / tags`
- 非核心内容明确 `indexable: false`
- `llms.txt / llms-full.txt / sitemap.xml / robots.txt` 同步更新
- About、首页、专题页承担“实体介绍”和“站点主题声明”

这层的重点不是继续堆技术，而是维持整洁度。

### 第二层：可理解

目标：让机器知道这篇文章回答了什么问题，适合谁，结论是什么。

这是当前最该加力的一层。核心动作有四个：

1. `标题问题化`
2. `段落答复式`
3. `文章边界清晰化`
4. `专题关系显性化`

如果一篇文章只是“我有感触”，它适合读者顺着读；  
如果一篇文章还能变成“某个问题的高质量回答”，它才更容易被搜索和 AI 引用。

### 第三层：可引用

目标：让文章中的关键段落被截出来以后，依然完整、可信、值得引用。

这层决定 GEO 上限。真正的可引用段落，通常同时满足这几个特征：

- 第一二句就给出判断
- 明确主语，不靠“它、这个、那种”支撑
- 有适用条件，不装成放之四海而皆准
- 有过程、案例、数字、工具名或反例
- 一段只讲一个核心观点

可以把它理解成：`不是写给浏览器看的，而是写给“被抽出来以后”也能成立的场景看的。`

## 四、文轩博客的内容战略：不是多写，而是先做强主题密度

### 1. 站点应该围绕的核心主题

结合现有内容，最值得继续深挖的不是泛 AI，而是下面四个主题簇：

1. `AI 工具与工作流判断`
2. `产品 / 创业 / 变现方法`
3. `自动化执行与项目复盘`
4. `个人成长与认知升级`

其中前 3 个主题最容易同时吃到 SEO、GEO、转化三重价值，应该优先建设。

### 2. 为什么不能继续平均发力

现在站里内容其实已经有方向，但还不够“专题化”。  
如果什么都写一点，搜索会觉得你不够集中，AI 也不容易把你识别成某个话题的稳定来源。

所以后续内容策略应该从“单篇爆发”切到“主题密集覆盖”：

- 不是再多写 30 个分散观点
- 而是围绕 4 个主题，各自打出 `支柱文 + 比较文 + 方法文 + 案例文 + FAQ 文`

这样才会形成真正的主题权重。

### 3. 建议的专题结构

#### 专题 A：AI 工具判断

适合承接：

- GPT vs Claude vs 豆包 vs Gemini
- AI 到底适合替代什么，不适合替代什么
- 如何判断一个 AI 产品的真正护城河
- 模型能力、工作流能力、产品能力的区别

适合做成的页面类型：

- 支柱文：`2026 年我如何判断一个 AI 工具值不值得长期用`
- 比较文：`Claude 和 GPT 在做项目场景里的本质区别`
- 复盘文：`我为什么在真实项目里放弃某个模型`

#### 专题 B：产品 / 创业 / 变现

适合承接：

- 普通人产品创业路径
- AI 时代的轻创业闭环
- 内容到信任到成交的路径
- 服务、产品、社群、自动化之间的关系

这会是最适合拿搜索流量的一个主题簇。

#### 专题 C：自动化工作流

适合承接：

- GitHub Actions
- RSS 自动化
- 定时任务
- 内容流、信息流、日报流
- 个人提效项目

这类内容天然适合答复式结构，也天然适合被 AI 和搜索引用。

#### 专题 D：个人成长与认知

这类内容不要停，但打法要变。

不是单纯写感受，而是把感受抽象成：

- 一个可回答的问题
- 一套适用边界
- 一段真实经历
- 一个行动方法

这样既不丢个人风格，也不会变成纯情绪输出。

## 五、单篇文章的重构标准：以后所有改稿都按这一套来

### 1. 单篇目标

一篇强 SEO / GEO 文章，至少要同时完成四件事：

1. 回答一个明确问题
2. 给出作者自己的判断
3. 能被抽成 3 到 5 个独立可引用段落
4. 能把读者继续导向站内其他主题页

### 2. 推荐结构

建议未来的核心文章都尽量向下面这个结构靠：

1. `核心结论`
2. `为什么会这样`
3. `判断标准 / 适用边界`
4. `案例 / 失败 / 过程`
5. `怎么做 / 行动清单`
6. `常见问题 FAQ`
7. `延伸阅读`

不是每篇都必须机械照搬，但核心骨架最好不要偏离太远。

### 3. 每段怎么写，才更容易被引用

每个重要 H2 后第一段，尽量满足这几个要求：

- 先答，再解释
- 主语明确
- 一段只讲一个判断
- 少用代词，多写对象名
- 补足场景边界
- 能带一点真实过程、工具、数字、步骤

#### 差的写法

“很多人都搞错了这个问题，其实本质不是这样。”

问题在于：有情绪，没有对象，没有结论，没有边界。

#### 更好的写法

“普通人做产品最容易失败的原因，不是技术能力不足，而是一开始就在解决自己不会高频使用的问题。只要创始人自己不是高频用户，需求理解、验证速度和迭代判断都会明显变慢。”

这类段落更容易被搜索摘取，也更容易被 AI 当成回答材料。

### 4. FAQ 怎么加才不会像机器人

FAQ 不是越多越好，而是只补用户真会搜的问题：

- 为什么……
- 适不适合……
- 普通人能不能……
- 先做哪个……
- 和另一个方案相比差在哪……

每篇补 3 到 5 个高相关 FAQ 就够了。  
FAQ 的作用不是凑结构，而是补搜索意图覆盖。

### 5. 内链最低标准

每篇核心文章至少做到：

- 链接 3 篇相关内容
- 至少有 1 个“同主题更进一步”的链接
- 至少有 1 个“相邻主题”的链接
- 至少有 1 个“作者立场 / 方法论”的链接

内链不是为了 SEO 小技巧，而是为了告诉搜索引擎和 AI：  
`这个站不是一堆散文，而是一套有关联的知识网络。`

## 七、怎么用 AI 真正做 SEO / GEO，而不是只让 AI 帮你堆字

### 1. AI 最适合做的部分

AI 适合接管的是“结构化增益”，不是“替你拥有观点”。

最适合交给 AI 的工作：

1. 从文章里抽出可搜索问题
2. 给旧文章补结构
3. 把段落改成更自包含的 answer block
4. 补 FAQ 草稿
5. 提取实体词、工具词、场景词
6. 生成内链建议
7. 做站内专题聚类
8. 发现哪些文章缺“结论段、边界段、步骤段”

### 2. AI 不该替你做的部分

不适合完全交给 AI 的部分：

- 最终观点
- 真实案例
- 失败细节
- 价值判断
- 风格和锋利度

因为文轩博客最值钱的部分，本来就不是“写得像百科”，而是：

- 你见过什么
- 你怎么判断
- 你为什么反对一种常见说法

AI 可以把这些东西组织得更强，但不能替代来源。

### 3. 建议的 AI 生产流水线

以后每篇核心文章，都可以按这套流水线做：

1. `选题识别`
   - 先写清楚这篇文章要回答哪个问题
2. `意图拆解`
   - 拆成 What / Why / How / Compare / Risk / FAQ
3. `文章扫描`
   - 找出哪些段落只有情绪，没有判断
4. `答复式重写`
   - 把弱段落改成 180 到 400 字自包含段
5. `实体增强`
   - 补工具名、平台名、时间、场景、过程
6. `内链补全`
   - 给每篇文章补 3 到 5 个合理站内链接
7. `元数据校验`
   - `description / tags / updated / indexable`
8. `审计复查`
   - 运行 `bun run geo:audit`
9. `人工收口`
   - 最后一定由你决定哪些句子保留锋利感，哪些句子不要过度“优化”

### 4. 基于当前仓库，下一步最值得新增的 AI 脚本

如果继续迭代基础设施，我最建议补下面三个脚本：

#### `cluster-audit.ts`

作用：

- 统计每个主题簇当前有多少文章
- 每篇文章属于哪个主题
- 哪些主题只有单篇，没有形成网络

价值：

- 帮你从“逐篇写作”升级到“专题运营”

#### `internal-link-suggest.ts`

作用：

- 基于标题、tags、实体词，为每篇文章生成候选内链建议

价值：

- 现在内链更像手工补充，后面应该半自动化

#### `answer-block-audit.ts`

作用：

- 识别哪些 H2 下面第一段没有直接回答问题
- 标记哪些段落过短、过虚、代词过多

价值：

- 这会比单纯总分更适合指导改稿

## 八、搜索视角和优化视角，要同时看

很多人做 SEO / GEO 只看其中一个视角，所以会越做越偏。  
文轩博客后面必须同时保留这两个视角。

### 1. 搜索视角

搜索视角问的是：

- 用户到底在搜什么
- 这篇内容是不是直接回答了这个问题
- 标题和摘要能不能匹配意图
- 这篇文章和站内其他文章有没有形成主题相关性

这个视角更关注：

- 关键词
- 搜索意图
- SERP 竞争
- 标题、摘要、FAQ
- 内链、专题页、索引能力

### 2. 优化视角

优化视角问的是：

- 哪些文章离起量最近
- 哪些段落改 20% 就能提升很多引用率
- 哪些主题值得持续投入
- 哪些内容应该合并、重写、降索引

这个视角更关注：

- 边际收益
- 优先级
- 资源分配
- 模板化改造
- 可持续运营

### 3. 两个视角合起来，才是正确打法

对文轩博客来说，真正有效的顺序应该是：

1. 先找“有主题潜力、有观点优势”的内容
2. 再把它们改成“搜索能识别、AI 能引用”的结构
3. 然后围绕表现最好的几篇，继续扩展成专题

不是“先研究一堆关键词再说”，也不是“我写得爽就行”。  
中间那条线，才是最适合你的。

## 九、相关项目与外部思路，怎么为这个站所用

之前调研过的外部项目，不需要全部接入，但可以作为能力地图来看。

### 1. 标准层

- `llms.txt`
- sitemap
- robots
- schema.org
- canonical

这层你已经基本补齐，重点是维护。

### 2. 抓取与抽取层

类似方向：

- Firecrawl
- LibreCrawl
- Crowl
- Crab

它们提供的启发不是“必须用这个工具”，而是：

- 未来可以把站点抓成统一文本层
- 再对这个文本层做专题聚类、引用评估、FAQ 提取

### 3. 审计与评分层

类似方向：

- GEO / AEO audit 项目
- AEOrank 一类的评分思路

你现在已经有自己的 `geo-audit.ts`，这条路是对的。  
但后面应该从“整篇分数”继续升级到：

- 主题分数
- 段落分数
- 内链分数
- 答案密度分数

### 4. AI 修复层

类似方向：

- prompt-based rewrite
- answer extraction
- content enrichment

这层正适合文轩博客，因为你的内容本身不差，差的是机器可提取度。  
这意味着你不是去“生成垃圾内容”，而是在做“高质量旧内容再加工”。

## 十、30 / 60 / 90 天执行方案

### 前 30 天：把高价值旧文改成站内支柱

目标：

- 把 5 到 8 篇核心文章改到平均 `60+`
- 建立清晰的内链网络

动作：

1. 优先改造第一优先级文章
2. 每篇补 `description / tags / updated / FAQ / 延伸阅读`
3. 每篇至少补 3 个站内链接
4. 复查首页、about、列表页的主题表达
5. 每周跑一次 `bun run geo:audit`

判断是否完成：

- 平均可引用性从 52 提到 58 到 62
- 至少 3 篇文章具备明显“支柱文”结构

### 31 到 60 天：从单篇优化，升级到专题运营

目标：

- 至少做出 2 个主题簇
- 每个主题簇有支柱文和配套文章

动作：

1. 选 2 个主主题先打透：建议 `AI 工具判断` 和 `产品 / 创业`
2. 每个主题新增 3 到 5 篇配套文
3. 建立更清晰的“主题页 / 标签页 / 相关文章”
4. 新增 `cluster-audit.ts` 或等价能力

判断是否完成：

- 站内不再只是单篇强文，而是开始有主题连续性

### 61 到 90 天：建立半自动 SEO / GEO 生产系统

目标：

- 让新文章天然按 SEO / GEO 标准生产
- 让旧文章定期被 AI 检查和迭代

动作：

1. 补 `internal-link-suggest.ts`
2. 补 `answer-block-audit.ts`
3. 把改稿流程写成固定 SOP
4. 对表现弱的旧文做合并、重写或降索引判断

判断是否完成：

- 不再靠“想起来才优化”
- 而是站点每发一篇、每更一篇，都自动更适合被搜索和 AI 引用

## 十一、你接下来最该亲自做什么

这部分很重要，因为很多 SEO / GEO 项目不是死在技术，而是死在作者本人没有持续提供“原材料”。

你最该亲自做的，不是去学更多 SEO 术语，而是坚持提供下面三类东西：

### 1. 更明确的判断

每篇文章都问自己：

- 我到底在反对什么常见说法？
- 我到底支持什么更具体的做法？
- 这个判断适合谁，不适合谁？

### 2. 更真实的过程

把这些细节多写进去：

- 你具体做了什么
- 失败在哪
- 为什么改主意
- 用了什么工具
- 花了多久
- 哪一步最卡

这些东西，正是 AI 最难伪造、也是最愿意引用的材料。

### 3. 更强的专题连续性

不要每次都从零想一个题。  
更好的方式是：

- 一篇支柱文
- 三篇配套拆解文
- 两篇反例 / 对比文
- 一篇 FAQ / 方法文

这才是长期会长出搜索势能的内容方式。

## 十二、文档治理规则

以后这件事就按下面规则走，避免再次分散：

1. `docs/seo-geo-system.md` 是唯一保留的 SEO / GEO 方法论文档
2. `reports/geo-audit.md` 是自动生成报告，不手写维护
3. 若后续新增脚本、流程、规则，优先更新这份文档，而不是再新开一个平行文档
4. 如果出现某个临时专题说明，结束后要么合并进这份文档，要么删除

## 十三、执行清单：以后每篇新内容都按这个 SOP 走

这一节是给“未来还有很多内容要输出”准备的。  
目标不是每次都重新想流程，而是让新文章天然符合 SEO / GEO 标准。

### 1. 选题入池清单

每准备写一篇新文章，先补 5 个字段：

1. 这篇文章回答的核心问题是什么
2. 它属于哪个主题簇
3. 它更像哪种角色：`支柱判断 / 比较辨析 / 方法流程 / 案例复盘 / FAQ回答`
4. 这篇文章准备连向哪 3 篇旧文
5. 这篇文章里你最想留下的真实经历或判断是什么

如果这 5 个问题答不出来，先不要动笔。

### 2. 成稿前检查

正文写完后，至少确认下面 8 件事：

- 有 `title / description / updated / tags`
- 开头有 `核心结论`
- 每个重要 H2 后第一段先答后讲
- 至少有 1 段带真实过程、失败或判断边界
- 至少有 1 组步骤、清单、表格或 FAQ
- 至少补 3 条站内链接
- 标题、描述和正文回答的是同一个问题
- 延伸阅读不是乱放，而是服务主题网络

### 3. 发文后执行命令

每次新增或大改文章后，按这个顺序跑：

```bash
bun run gen:meta
bun run geo:audit
bun run cluster:audit
bun run link:suggest
bun run answer:audit
```

如果想一次跑完，就直接执行：

```bash
bun run geo:execute
```

### 4. 读报告时怎么判断优先级

看报告不要平均改，按下面顺序判断：

1. 先看 `geo-audit.md` 里平均分最低、但主题价值最高的文章
2. 再看 `answer-block-audit.md` 里哪些 H2 首段最弱
3. 再看 `internal-link-suggestions.md`，优先补没形成站内网络的核心文章
4. 最后看 `cluster-audit.md`，决定下一个新选题该补哪个主题角色

### 5. 周节奏建议

如果后面内容会持续增加，建议固定成下面节奏：

- 每周 1 次：跑 `bun run geo:execute`
- 每周 1 次：补 1 篇旧文的结构和内链
- 每周 1 到 2 篇：围绕主主题发新文
- 每两周 1 次：检查主题簇是不是越来越完整，而不是越来越散

### 6. 新内容生产节奏

优先级固定成这三层：

1. `先补主题缺口`
2. `再写同主题配套文`
3. `最后才发临时灵感文`

更具体一点：

- 如果 `cluster-audit.md` 说某个主题缺比较文，就优先写比较文
- 如果某篇支柱文流量潜力高，就补它的 FAQ 文和案例文
- 如果某个主题已经有支柱文、方法文、案例文，再考虑外扩新方向

### 7. 你亲自负责什么，脚本负责什么

脚本负责：

- 生成元数据
- 发现弱段落
- 给出内链建议
- 判断主题覆盖

你亲自负责：

- 真实判断
- 真实过程
- 最终标题
- 最终语气
- 哪些观点值得继续深挖

这样分工最稳，因为它既能扩产能，又不会把站写成模板工厂。

## 最后一句话：文轩博客下一阶段，不该继续“写更多”，而该“写得更能被机器理解”

你现在最有价值的资产，不是流量技巧，而是已经有一批带判断、带风格、带真实经验的文章。  
这本身就很难得。

接下来真正要做的，是把这些内容从“好读”再推进一步，变成：

- 可索引
- 可提取
- 可引用
- 可串联
- 可持续复利

如果这个方向做对了，文轩博客最后拿到的不会只是搜索流量，而是一个更像“作者知识资产库”的东西。
